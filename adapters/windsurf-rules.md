# AI 开发完整工作流（Windsurf 规则片段）

## AI 开发流程规则

一旦规则被触发，所有**写代码**类任务须按以下顺序执行（纯问答不触发）。

1. **实现规划（必须先做，且不改代码）**：调查框架、构建/测试命令、相关模块；产出 `specs/plans/<slug>.plan.md`，包含验收标准、现状、方案与被否方案、文件级变更清单、分步任务、测试策略、风险、敏感代码判定、执行命令。需求模糊先产出 `specs/prds/<slug>.prd.md`（仅 what/who/why）。
2. **确认门**：计划写完**暂停等待批准**；不得自行进入实现。
3. **按批准指令选择路径**：
   - 带 TDD 指令（如「严格使用 tdd-workflow 实施」）→ TDD：RED（测试先失败）→ GREEN（最小实现）→ 重构 → 覆盖率 ≥80%；
   - 仅 `yes/ok` → 普通实现 + 关键路径测试。
4. **代码审查**：审查者视角查正确性/边界/并发/一致性/规范/测试有效性，Blocker/Major/Minor 分级 + `文件:行`，写入 `specs/reviews/<slug>.review.md`；Blocker 修复后重跑测试。
5. **敏感代码判定 → 安全复查**：认证/授权/Token、外部 API/Webhook、敏感数据(PII/支付/密钥)、上传下载、反序列化、SQL/命令拼接、依赖变更 → OWASP 逐项审查，写 `specs/reviews/<slug>.security.md`；非敏感写明跳过原因；不通过不得收尾。
6. **收尾**：修构建/lint/类型错误（禁 `@ts-ignore`、`eslint-disable`、删测试掩盖；连续 3 次失败即停并报告）→ diff 与计划核对 → PR 描述经确认后创建。

禁止：确认门前改源码；擅自 push / `reset --hard`；跳过安全复查。
